# Karolina 工程工作台

独立 Windows 程序，源码在 Tools。使用 .NET 8、Codex 和 Unity MCP，不要求工程有 Git 仓库。页面由微软官方 WebView2 SDK 1.0.4258.31 和机器上的 WebView2 Runtime 承载，HTML 仍由本机服务提供。只有一套 Windows 标题栏，不启动或嵌入完整 Edge 浏览器窗口。

## 启动

```powershell
powershell -File Tools/Karolina/Start-Karolina.ps1
```

指定工程可传 `-ProjectPath E:/Unity/Item/FrameSyncMobaDemo`。唯一程序输出为 `Tools/Karolina/artifacts/current`，启动入口始终相同。更新前从托盘“完全退出”；启动脚本构建到 current，旧生成输出可恢复地移出程序目录，不再新建 GUID 版本目录。服务仅绑定随机 127.0.0.1 端口，API 需要本次会话令牌。

## 页面与操作

- **外观与组件**：粉、青、紫主色、深空工作台主视觉、K 蝶、看板娘与几何 Agent 手机表情。按钮框内居中无尾三角表示悬停和选中，组件样式拆为独立小件。提供深浅配色、轻量/关闭动效、静态背景、可回退的 WebGL Shader；主题包支持组件 CSS、图标、字体、背景、角色与 Shader 的部分覆盖、导入/导出和按工程保存。详见 [自定义指南](THEMES.md)，最小示例在 [ThemeTemplate.zip](Design/ThemeTemplate.zip)。

- **AI 对话**：启动自动连接本机 Codex app-server，并尝试 Unity；失败在空闲时重试。获取真实模型、思考档位和登录账号；可选只读、工程写入或完全访问；新建/继续对话、流式回复、工具详情、批准/拒绝请求与停止。提供讨论需求、制定计划、执行任务三个入口；前两者限定文档写入范围，尚不自动解析回复为结构化需求案或计划案。参考资料将需求与计划混排并明确类型，可按类型筛选、浏览标签、按标题/标签部分文字搜索，默认隐藏废弃/关闭项，按编号自然倒序；可空选或多选，显示标题与状态并支持标签检索。勾选计划默认包含其全部真实关联资源，支持逐项或全部取消。模型、思考档位、权限菜单统一向上展开。选择资料只增加上下文，不自动批准需求或宣告验收。执行任务另选一份执行计划，用于任务基线和审批。
- **需求案／计划案／规则案**：对应 Docs/requirements、Docs/plans、Docs/rules；规则固定为工程事实、执行细则、项目索引、模板四个板块。正文显示标题、目录、表格、代码、引用和任务列表；可编辑未结束的正文、创建需求/规则与计划草案，保存检查外部修改并备份旧版本。公式块显示可读源码，目前没有数学排版器。目录按 h1–h6 分层折叠，最浅级默认展开；Ctrl+滚轮仅缩放Markdown，导航/目录/输入与Windows窗口保持固定，正文百分比按钮可恢复。标题目录有展开全部/折叠子级和窄窗入口。需求演进由正文派生最近在前的完整时间线。元数据入口可编辑最多10个标签，计划另有事前增改删预估与实际资源关联；关闭计划可补索引，不重启生命周期。
- **任务审批**：任务开始前记录 Assets/Packages/ProjectSettings 基线，只审批确认属于Agent的实际变化。成功Codex文件补丁必须核对冻结版本与写后内容；命令/MCP及同期人工变化缺乏逐文件证据时列来源待确认，人工素材不参与批准。不按.anim等扩展名猜作者；可填依据批量确认或更正，确认必须绑定所看文件版本。.meta永久略过，无开关。差异在后台自动更新，不需人工提交差异，按钮仅“保存任务摘要”。每个文件先读具体操作、原因、验证限制与说明来源；资源不展示YAML、二进制、统计或原始资源差异，代码说明后保留代码diff。说明绑定冻结指纹，缺失时不能批准Agent文件。可只读补充旧差异说明，不能据此证明原作者或验收。审批页独立选择说明模型/档位，默认优先服务返回的mini/nano/luna与低档，不识别时要求手选；显示任务/轮次绑定的阶段、耗时、输出字符数、实际保存文件数，可停止同一轮次，最近生成状态本地持久化。逐文件结论、行意见、整体批准/退回及原会话再执行保留；内容改变需重新审，前端草稿受保护。整体批准后计划关联实际Agent文件与审批证据。状态持久化到工程 .karolina/state，完全退出后恢复；批准不回滚、不提交Git、不自动关闭计划。
- **拓展工具**：操作指南独立于规则，资料位于 Docs/tools/guides，工具声明位于 Docs/tools/registry。支持说明类、Unity MCP 和外部进程工具，每项附使用说明；实际调用按注册参数与权限执行，未知或未注册能力不由界面虚构。工具页提供工程实际本地/UOS客户端、服务端、双端构建菜单、发布参数窗口及两个GUI启动器；移除Console、Editor状态、.NET环境独立工具。GUI模式只返回启动PID，不等待用户退出；配套说明也可编辑标签。
- **底栏**：Codex 和 Unity 连接状态。点击 Unity 打开工具抽屉，核对工程、读取 Editor/Console、刷新脚本或运行指定程序集和类的聚焦测试。
- **运行详情（仅 AI 对话顶部）**：可选诊断抽屉，保留请求、权限、会话、终态、错误和 Unity 回执，用于查明停止是否成功、为什么没有返回、测试是否实际执行。普通讨论不必管理记录；它不代替需求、计划或验收。

Docs 分类、模块、正文、元数据和机器事实 JSON 文件均使用英文路径；正文和 UI 模块/标题为中文。新建提供英文文件标题/英文模块目录；文件用编号加英文标题，同名 `.meta.json` 保存索引、关联、版本、来源与证据。只有需求在正文记录详细演进，元数据无 history。计划分准备、执行、测试（机器/Agent）、校正、验收（人工）、关闭；关闭不重启，规则无状态。

窗口原生最小化按钮进入 Windows 任务栏；原生 X 收起到系统托盘，任务继续。双击托盘或选“打开 Karolina”恢复；托盘“完全退出”关闭窗口、本机服务和本程序拥有的 Codex/WebView2 子进程。网页没有自制窗口按钮，也没有浏览器标签页/内层窗口按钮。活动任务退出保留已写文件，需要后续核查；不回滚工程。同工程写锁限制 Karolina 操作，不能阻止其它 IDE、终端或 Unity。

## 外部操作与后续范围

未登录时在终端执行 `codex login`，然后刷新连接。场景精细编辑、实际游戏观察仍在Unity完成。Karolina可调用现有构建菜单或启动GUI，实际构建和游戏仍由Unity/对应启动器执行；构建请求发送一次后暂停Unity操作和Harness新轮次，等待用户确认结束。

AI 回复到结构化需求案／计划案的自动创建、Jev、CodeGraph、ResourceGraph、可编辑 ArchitectureGraph、自动测试修复、自有 MCP、多 Harness、自动续接和模型档位映射保留在最终产品需求，本期没有实现。拓展工具已有最小注册与调用入口，复杂编排仍属后续范围。
