# 任务变更审批与集成规则

## 界面范围

独立 [Karolina 工作台](https://github.com/Mosya-CX/Karolina) 提供按计划任务的 Unity 文件差异与人工审批。其产品合同见工程文档 [REQ-KAR-006](../../requirements/karolina/REQ-KAR-006_task-change-approval.md)。旧 Git 工作区产品功能退役；常规版本管理、账号登录、拉取和历史由用户外部 Git 工具操作。用户本轮新授权状态栏的专用 Agent 分批发布，合同见 REQ-KAR-018；这不恢复全功能 Git 页面。稳定规则编号保留，规则归入执行细则。

## 任务边界

写任务开始前清点真实 Assets、Packages、ProjectSettings 内容，包含未跟踪资源与 .meta；不以 HEAD 推断一次任务变更。开始前已有工作保留，生成本次任务的前后内容版本。外部任务必须先记录基线再执行，同期 IDE/Unity 写入不能被声称是某个 Agent 的独有修改。

## 人工审批

单个文件可通过、不通过或保存文件/行意见；不通过需要解释。整体批准显式接受待定文件，已有不通过文件必须处理。审批核对修订、路径及真实内容，拒绝陈旧结论；再执行后保持未变化文件的审批，已变化文件重新待审批。

整体不通过进入待再执行，保留原基线及退回意见，成功载入原会话后回到 AI 指令；用户发送后继续执行。外部任务无原会话或原会话已删除时新建对话，保留原任务与基线。审批不直接改写、回滚、提交或合并 Unity 文件，不自动关闭计划，不替代机器验证或 Codex 扩权审批。

## 存储与失败

任务记录及文本快照位于工程内 `.karolina/state/reviews`，该目录由 Git 忽略，不由浏览器端口或本机启动方式决定。首次恢复旧本机记录保留编号和原文件，后续写入以工程状态为准；链接、来源身份不符和恢复冲突拒绝且可见。正文需求演进、计划生命周期和任务轮次证据职责分开。越界/链接、读写冲突、内容已变和存储失败必须可见。审批编辑保存时锁定编辑与切换，失败保留输入；跨页面保留草稿，退出提示包含审批草稿。

## 验证边界

行为检查只能使用临时工程及真实协议/鼠标键盘，不用截图；不能把旧 Git 检查数字当成新版审批通过。用户未要求本轮行为测试时登记“尚未执行”，只报告真实编译和源码审查。除用户启动 REQ-KAR-018 专用发布任务外，Agent 不自动执行生产 Git 写操作。

## 已中断任务的事后整理例外

用户明确要求整理已有中断任务时，可由维护入口导入有证据的文件集合。必须显式显示“事后整理（历史参考）”、参考来源与逐文件依据，不以 HEAD 证明作者或任务开始版本；未选已有文件以整理时内容为基线，真实条目全部待审批。此例外不改变正常任务执行前记录实际快照的要求，事后整理不自动授予 Git 写权限。


## 来源归属与后台同步

快照变化不是作者证明。审批候选按内容指纹区分Agent、人工、未知；只收录确认Agent的版本。人工提供的素材直接排除审批，扩展名不是归属依据。Codex成功文件变更回执必须验证补丁作用于冻结前版且与当前内容吻合；普通命令或UnityMCP调用无可核对逐文件回执时列未知，允许人工明确确认。未知不能整体批准。`.meta` 仍留真实基线，但永久不显示、不审批，无显隐开关。

文件监听去抖与增量快照用于后台异步同步，保存摘要独立于差异刷新；失败可见重试。未变文件的保存意见/决定保留，内容变化使旧来源/批准失效；前端未保存草稿保留并提示更新。批准前完整读取校验当前内容与修订。审批正文必须有与冻结指纹一致的逐文件操作说明；资源不展示YAML、二进制或原始序列化差异，代码保留diff。只读补充说明不证明原作者、实际执行或验收通过，不能改变Origin/Decision/Notes。缺少当前版说明不能批准Agent文件；可保存意见或退回补齐。


## 专用发布与一次性回滚（用户本轮授权）

1. 未审批计划、未批准当前版本、未知来源和夹杂未审批内容的共享文件不推。三狼未完成内容不推。
2. 按功能和职责细分：核心合同与服务、桌面接口、前端交互、测试、需求/规则文档分别成批；强关联改动一起提交，不能拆出无法工作的中间版本。
3. 标题用简体中文“模块：具体动作”，例如“对话：折叠附加参考资料”。正文中文说明变更、原因、真实验证与限制。编号作引用，不代替可读标题；不写泛泛的“更新文件”，不编造测试通过。
4. 不覆盖用户暂存，不 force push，不 pull、stash、clean，不执行整仓库回滚。GitHub 账号沿用外部 Git 凭据管理，不在设置保存密钥。
5. 额外规则最多 300 字，只能增加约束；任务日志区显示中文进度、批次及失败原因，不显示大量 CLI。


Git 默认可读；回滚能力限定来源版本和文件，消费一次后失效。普通任务临时写授权进入待审批即回收，退回重新申请；规则写权限须明确截止时间。发布 Agent 工程只读，只获得专用执行器允许的 Git 能力。关闭文本不能代替人工发布批准。状态栏发布只面向当前目标工程，不能选择 Karolina 自身或其它仓库。Karolina 自身改造与 Git 集成由外部 Codex 执行，运行时不提供自身计划审批或批准表单。推送面板只常显300字以内的额外规则与推送按钮，进度/重试按需出现；一次性回滚由Agent在对话内申请，人工确认具体文件、来源提交与期限后，原轮次执行一次即失效；规则/工具的临时权限同样由对话内申请，不能通过独立面板提前授予。
