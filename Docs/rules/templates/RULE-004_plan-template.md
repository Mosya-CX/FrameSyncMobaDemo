# 计划案模板

## 参考需求

链接具体需求与章节。requirements 是编号；requirementRefs 保存引用时标题、状态、版本、章节、路径与 hash。准备可尚未关联；执行前不可空引用。

## 实施细节

给出文件/程序集、现有与待改类型、算法具体步骤、结构/字段、数据流、依赖、快照与资源操作。每份计划限定独立批次，不把多年执行合并成永久重启的计划。

## 六阶段与进度

1. 准备：调查、选定方案、确认关联需求与测试设计。
2. 执行：按编码顺序修改，登记步骤与未完成范围。
3. 测试：真实机器构建/测试、协议和行为检查，加 Agent 审查。源码核对与实际测试分别记证据。
4. 校正：测试或人工验收发现修改需要时进入，定位原因后回执行或测试；无问题可直接测试→验收，不补造校正经历。
5. 验收：用户人工使用确认，记录实际结果；不由 Agent 自动填“人工通过”。
6. 关闭：人工结论明确后结束并冻结。关闭后不重启，后续新计划承接。

转换图：准备→执行→测试；测试→校正/验收；校正→执行/测试；验收→校正/关闭。关闭是唯一终态。取消的历史结果记录 outcome，不扩充六阶段。普通后续改造建立新需求，长期需求澄清保留自身正文演进。

## 机器测试与 Agent 审查设计

写具体函数/类、程序集、场景/夹具、输入、工具、预期断言、失败处理与回执。编译不等于行为通过，EditMode/PlayMode 各验相应范围，构建不能用 Editor 测试替代。高风险用独立只读 Agent 审查。

普通“执行任务”应自动执行本计划的测试；项目测试按钮仅用于人工复现、复测和验收辅助。制定计划时必须按通用模板描述以下六层，不让 Agent 临场依靠鼠标操作或凭回复判断结果：

先用project_test_capabilities检索可复用场景、适配器、领域动作和采样字段。显式登记的覆盖不等于本次机器通过；图谱/词法方法候选须读源码确认。正文写清复用哪些能力、还缺哪些能力，复现条件列输入、实际依赖版本、时间域和可选种子。综合测试采用PreparedRuntimeRunner的有序条件动作及项目时钟，不依赖Agent每帧模型往返。动作后重新采样，超时/采样上限/取消均有真实结果和清理；缺口不可通过弱化原断言填平。

1. 运行态准备：隔离场景/世界、依赖替身或真实依赖、初始数值、运行时生命周期。
2. 预输入：具体 API/命令/预编排输入、顺序、参数、推进条件。
3. 采样：字段、位置、频率、时间坐标、run/scenario/attempt 关联和丢弃/错误信息。
4. 分析断言：预期值/容差、采样关联、成功与失败判据，不能只检查“无异常”。
5. 清理：正常、失败、取消后的回收动作和完成判据，保护工程原有状态。
6. 失败诊断：定位无进展或默认两轮修复仍失败时，需要增加哪些采样；保留原断言，额外生产修复等待批准。

计划独立元数据的 `testDesign` 保存 `mode`（`required` 或 `not-applicable`）、`cases`。每项包含 `checkId/preparation/input/sampling/assertions/cleanup/diagnostics`，与 `verificationChecks` 一一对应；执行入口只在 `verificationChecks` 声明，不复制另一套命令。场景检查使用 `kind=scenario`、`toolId` 指向 `Docs/tools/test-scenarios.json` 中已登记的入口；普通命令/拓展工具仍可使用。新增测试文件可以在准备阶段声明，实际执行前必须存在。不适用机器测试时填具体 `reason`，不可伪造通过。

首个工程写操作前冻结设计和入口，实施后宿主自动运行原检查、独立只读复审和有界修复；缺少设计/回执、环境未就绪或复审失败就暂停，不自动交付审批。任务进度、真实资源索引可以更新，不能弱化已冻结断言。通过机器与 Agent 验收也不等于人工验收，仍需用户确认。

## 人工验收和结果

写用户能操作的入口、重点场景、期待表现和实际人工反馈。自动通过后保持验收阶段，人工确认才关闭。不以截图代替本轮验收。

## 恢复与独立元数据

保护任务开始前工作，说明撤销范围、schema/GUID 兼容与外部依赖。元数据：id/code/title/type/status/domain/path/version/requirements/requirementRefs/sources/evidence/assessment/closedAt/conclusion/outcome。没有 history/evolution。activePlan 定位本轮活动计划。


## 文件预估与真实资源索引

准备阶段在独立元数据 plannedChanges 登记规范路径、operation（add/modify/delete）和原因，进入执行前不可缺失。实施有偏差时更新预估与进度。resourceRefs 单独登记真实文件路径、关联依据、冻结哈希与任务审批编号（如有）；删除项保留路径及删除证据。旧关闭计划仅补充有证据的资源关联，不伪造事前预估或重启生命周期。机器精确路径扫描只证明文件关联与存在，不证明完成、作者或测试通过。无法确认列清单。所有案的 tags 最多10个、去空去重；标签/资料索引补充不形成需求演进。
