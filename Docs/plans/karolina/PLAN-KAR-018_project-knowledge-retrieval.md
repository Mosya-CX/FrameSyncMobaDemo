## 实施细节

1. Core 新建 KnowledgeChunks：Markdown 标题栈、代码声明及有界行窗口，块保留来源 hash、行号、标签、状态与身份。代码声明仅为启发式定位。
2. ProjectKnowledgeIndex 单工作者维护文件块快照；观察器合并变化，周期校对，复用文件指纹，持久化含工程根和 schema 的原子 JSON，错误保留旧索引。限制扫描目录、文件大小、总块数及链接路径。
3. KnowledgeSearch 构建倒排词项/BM25，中文二元分词与英文符号拆词，支持部分词。DeepSeekRetrieval 用官方 JSON Chat Completions 改写问题、补充同义及英文查询；多个本地 BM25 排名 RRF 融合，限定文档/代码名额及每来源块数。
4. ProjectRetrieval 编排索引搜索、文档明确关系、实际资源和图谱邻接；所有返回证据在返回/打开前重新检查当前路径、读取策略和指纹。Desktop 将宿主真实登记的任务验证状态投影为单独证据，重新核对输入与验证定义，不能由计划文字生成通过结论。提供来源详情，不返回二进制/YAML长正文。
5. Desktop 组合服务；project_search、自动参考、手动资料共用检索。默认复用当前 Codex 对话模型理解问题、迭代调用 project_search 核对证据，沿用当前账号和模型，不额外创建辅助对话、不要求另一份 API 密钥。自动词项召回只是初选，模型按需补查；手动搜索默认是词项搜索。DeepSeek 仅作用户主动启用的可选前置查询改写。
6. UI 显示章节/行号、片段及打开来源，自动资料默认收起；统一设置页显示索引状态、默认 Agent 工作方式和可选 DeepSeek 配置，不导航到新页面。密钥由设置页填写并存入 Windows 凭据管理器；不新增第三方包、不安装本地模型。

### 校正方案细化（已批准，实际结果见本轮校正记录）

上一轮仅细化方案，随后用户明确批准执行。以下保留校正目标和验收意图；本轮实现、实际参数及未达稳定效果的部分以“本轮校正实施与复测”节为准。默认继续使用当前Codex对话所选模型，不增加本地模型、外部API或隐蔽辅助对话。下文“召回”表示搜索服务找到候选资料，“注入”表示候选资料真正传进当前模型上下文，两者不能混淆。

#### 1. 文档状态与引用：事实由程序读取，模型负责解释

**现在的问题**：PLAN-KAR-017的元数据明确写“验收”，模型却说“进行中”；部分quote是模型拼接或改写的文字，虽然大意可能正确，却不是真正逐字原文。

**建议怎么改**：

1. Core的RetrievedReference补齐文档编号、类型、当前状态、版本、元数据来源与指纹。检索和打开来源时都核对正文及这些字段；修改元数据后旧状态不能继续作为当前证据。
2. Agent引用时提交来源ID和行范围；宿主只允许引用实际已读取且仍有效的来源，按当前文件取出对应原文。不存在的ID、越界行号、已变化来源应拒绝并要求重新检索。可先通过project_search返回完整的有界证据；新增只读来源工具时复用现有Source核对，不另建一套绕过权限的读取逻辑。
3. 引用卡片、状态标签由程序生成。模型可以概括含义，但概括与原文用不同样式呈现，不把概括放在“原文”位置。模型没有引用或无法核对时显示“未核对来源”，不伪造可点击证据。
4. 计划阶段、机器验证、人工验收分别展示。例如“计划阶段：验收；人工通过：未登记”，不能由模型把它们合并成“已经完成”。结构化卡片不接受模型文字覆盖；模型自由正文仍可能出错，不能承诺完全消除模型错误。

**你能看到的效果**：问“017能关闭吗”，出现真实状态“验收”和“尚无人工通过记录”；点击引用看到对应文件的准确原句，而不是模型重新组织的句子。

**重点验收**：先读取再修改计划元数据，旧引用应失效；测试不存在的引用ID、错误行号、拼接quote；机器通过不能把人工状态变成通过。

#### 2. 口语与跨模块检索：先理解问题，再找具体实现

**现在的问题**：问“同一个招式为什么要等一阵才能再按”，词项搜索没找到AbilityRuntime；问金币如何确认，找到需求却漏掉GoldIncomeRuntime源码。“星门熵聚合器”的问题不存在，仍因“工程、实现”等泛词带回17条资料。

**建议怎么改**：

1. 保留原始查询；精确编号、文件路径和完整符号优先，不被同义词查询冲淡。
2. 当前对话模型根据工程提问生成少量具体查询。例如“招式等一阵”转为“技能 冷却”“cooldown”“IsReady”；这些只是搜索线索，搜索前不能断言工程就存在这些类型。
3. 找到文档后读取其明确源码关系，再沿实际符号和有证据的图关系补查。金币题应同时补齐“需求规定谁拥有收入”和“源码哪个入口确认收入”，不是只返回更多同类文档。没有明确关系时允许普通只读文件搜索。
4. 排名时减少泛词作用，记录关键词覆盖、精确命中及关系依据。阈值由有答案/无答案样本校准，不用一个未经验证的BM25分数直接宣称置信概率。低相关候选可作为补查线索，但不能当成直接回答依据。
5. 返回“已找到直接证据”“仅有相关线索”“没有匹配”三种资料情况。尚未检索到实现时明确说证据不足，不把它变成“全工程不存在”。
