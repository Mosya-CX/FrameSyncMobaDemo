# 工程图谱后台自动更新实施

## 参考需求

[工程代码与Unity资源关系图谱](../../requirements/karolina/REQ-KAR-013_project-code-resource-graph.md)：技术方案、边界情况、验收条件及2026-10-07自动更新演进。

## 准备

检查ProjectGraphService索引、文件监听和启动缓存核对，以及3D页面载入逻辑。现有监听只标记过期；增加后台调度而不扩大扫描范围，不引入包，不修改Unity源码和资源。保留三狼activePlan。

## 执行

1. Core新增ProjectGraph.Refresh部分实现单调度循环，500毫秒检查；1.5秒去抖、持续变化最多15秒。初次无缓存和旧缓存不一致自动排队，手动刷新沿用同一索引互斥。
2. 文件/元数据/新增删除事件标记stale并排队，重建中变更保留changeVersion并再排下一轮；不重复并发扫描。
3. 在后台构建快照与查询索引，原子发布JSON和内存版本。旧快照在重建期间仍能查询；失败保留旧快照，错误可见，15/30/60/120秒退避重试。状态携带下一次自动重建时间。
4. 索引遍历响应取消，Dispose注销监听、取消调度并等待后台结束，防止退出后继续写缓存。
5. 页面显示待更新/更新中/失败重试；成功自动加载快照，保留相机和仍存在的选中节点，离开图谱页面也继续更新。

## 测试（机器与Agent）

GraphRefreshChecks验证无手动首建、代码和资源GUID更新、连续变化合并与旧图查询、重启核对、meta/删除、失败保留与真实退避重试、生成目录忽略及退出不写缓存。GraphSettingsChecks保持覆盖与查询语义；ProjectGraphViewChecks保持布局/相机算法。GraphRefreshLiveChecks在临时工程用真实浏览器验证没有手动索引请求仍自动更新，3D节点数量和相机保持，切回对话不跳页且草稿保留。真实工程页面检查输入/主题/连接。不截图，不运行Unity构建，后台生命周期由独立只读审查复核。

## 校正

保留真实失败和修复证据；不能把旧图可用当成新索引完成。测试选择器歧义只修正精确按钮选择，不弱化自动更新与视野断言。

## 验收（人工）

## 关闭

人工验收后冻结；后续性能或增量索引独立立项。
