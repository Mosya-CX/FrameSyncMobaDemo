1. Core 权限服务编译 filesystem read/write/deny；任务授权保存失效状态且不复活。Desktop 发送命名 permissions，移除完全访问选项；统一设置按内容角色维护位置。
2. Core 发布准入服务以人工回执、计划状态、文件 SHA256 判断是否允许。未完成计划的 plannedChanges/plannedExternalChanges 与审批文件冲突优先拒绝。
3. Codex 发布分组器接口与 Git 执行器分离；前者隔离且只读，后者用临时索引、预期 HEAD 更新、路径复核保护暂存。任务持久化中文进度与提交回执。最多 300 字额外规则，默认 Luna 最高。
4. 状态栏面板显示可推送/排除原因、进度和失败重试；统一设置保存发布模型。回滚按固定来源与当前指纹预览并发放一次性能力。
5. 核对已有 Karolina 计划结案：关闭 005、006、007、009、010、011、012；008 的最终 PSD 未交付，继续执行。历史远端存在不代表当前本地修正已推送。

## 数据流与算法细节

仓库 diff/untracked → 规范相对路径与当前 SHA256 → 任务批准/结案回执 → 未审批计划覆盖优先拒绝 → 冻结发布快照 → 只读 Agent 结构化分组 → 覆盖完整、无重复、无越界、中文标题校验 → HEAD/索引/远端/批准版本再次核对 → 临时索引 write-tree、commit-tree、update-ref 预期旧值 → 保留原暂存的索引合并 → 普通 push → ls-remote 核对。

回滚：预览固定 commit 和 file hash → 人工借用单次能力 → 执行前消费能力 → 再核对工作树 hash → git restore --worktree 指定文件；索引和 HEAD 不变。任务授权在状态离开执行或期限到达时持久回收；执行轮次使用过期授权时必须中断并清理终端。
