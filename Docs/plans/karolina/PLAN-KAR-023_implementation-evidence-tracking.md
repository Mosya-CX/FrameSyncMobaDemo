# 需求实现证据追踪与过期复核实施

## 参考需求

- [REQ-KAR-028：需求实现证据追踪与过期复核](../../requirements/karolina/REQ-KAR-028_implementation-evidence-tracking.md)：实现状态证据快照、计划/文件指纹校验、旧数据基线和自动失效回退。

## 准备

调查当前 `DocumentLibrary` 的状态写入、需求 `evidence`、计划 `requirementRefs/resourceRefs/externalRefs`、RAG 状态传播、Workbench 事件轮询和文档详情抽屉。实现采用 Core 纯业务证据核查、Desktop 路由/后台调度、Web 展示三层；外部文件哈希仅允许精确匹配当前 Karolina 应用仓库。

本工程现有 145 份需求已有独立生命周期和实现状态。旧“已实现”记录没有统一快照，首轮扫描不得批量降级：证据完整且指纹可核对时自动保存当前基线；缺项或无法读取时保留状态并标为待复核。

## 实施细节

1. 新增 Core 证据核查模型和 `DocumentLibrary` 部分实现。以需求编号汇总直接 `evidence` 和所有关联计划；只纳入源码/测试代码，记录计划归属，按文件读取当前 SHA-256。
2. 快照保存于需求 `.meta.json` 的 `implementationEvidenceSnapshot`，包含需求正文哈希、已关闭计划编号/正文哈希/需求关联与资源指纹、源码/测试仓库路径及 SHA-256、采集时间。另用最新 `implementationEvidenceCheck` 记录当前失效原因，不写需求演进历史。
3. 计划证据只从 plans 的 `requirements/requirementRefs` 关联；对执行中计划，不作为已完成证据。`resourceRefs/externalRefs` 的一般资源关联只用于定位，不推断测试通过；计划 `evidence/assessment` 的测试状态照录。
4. 在 Workbench 增加后台首轮与每五分钟周期审计，并提供按需单需求检查接口。采用 `WorkspaceLock` 和元数据 SHA 乐观并发校验。发现明确失效时只重置该需求为待实现，记录原因并发 UI 事件。
5. 更新实现状态写入路径：从待实现改为已实现时，要求可核验的已关闭计划、源码和测试证据，写入新快照；恢复待实现时清除当前快照但保留最新失效说明。新演进仍由既有保存路径重置；纯格式修订更新快照里的正文哈希。
6. 在需求文档“文档信息与关联”抽屉提供轻量“实现依据”页签，以摘要、计划卡片、源码/测试文件状态和验证记录展示；明确区分文件指纹、机器执行和人工验收。过期事件刷新文档列表并显示单条汇总提醒。
7. RAG 索引继续读取现有 `implementationStatus`；状态恢复后检查索引快照失效/刷新路径，确保不会将旧状态当作当前事实。
