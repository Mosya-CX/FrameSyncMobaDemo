# 后台测试与测试对话清理实施

## 参考需求

- REQ-KAR-026：后台测试与测试对话清理；本计划覆盖来源登记、清理生命周期和后台输入。
- REQ-KAR-025：方法取证与检索效率；已有评测汇总证据保留，测试对话正文应删除。

## 准备

读取两个仓库执行规则。旧工作区变更不重置、不提交。使用准确评测回执、临时工程 run.json 和空归档线程组合证据建立清单；独立只读审查核对范围与递归删除风险。工程 Gameplay、Unity 资源、三狼计划不改动。

## 执行

### 测试对话生命周期

创建临时工程 -> 写来源登记 -> 创建线程后登记准确 ID -> 执行测试 -> 保存无对话正文的通过失败统计 -> 正常停止自建宿主 -> 列出线程关系并核对来源 -> 官方永久删除 -> 删除准确本地 run 及测试 chats 条目 -> 写清理结果。未确认停止、来源不符或未知派生线程时中止相关删除。

### 后台输入架构

Desktop 的显式后台测试入口验证临时工程标记，隔离浏览器资料，跳过 last-project 更新。Window 保持不激活且移出可见桌面，隐藏托盘，后台错误报告而不弹模态框。测试进程通过已有 Playwright/CDP 向实际 WebView2 派发输入事件；Python 辅助程序只读采样前台窗口与光标位置，不注入系统输入。

## 测试

- 构建解决方案，期望 0 警告/错误。
- 清理单元检查覆盖未退出宿主、错误工程、活动/固定线程、外部派生、分页失败、官方删除错误及目录越界；所有危险情况无删除调用。
- 真实 Codex 只创建/归档空线程，不调用模型，验证测试结束后永久删除、再读取失败，Karolina run 消失。
- 后台 WebView2 检查设置输入、夹具对话、目录搜索、文档保存和审批意见，检查前台采样与目标工程未变化。无需移动用户鼠标。
- 禁止截图验收；不运行正式 Unity 构建；不把渲染器输入当成 Windows 输入法和托盘通过。
