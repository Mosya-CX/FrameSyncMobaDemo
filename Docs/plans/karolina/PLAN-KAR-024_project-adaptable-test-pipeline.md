# 通用项目测试与诊断流水线实施

## 本轮补充：预编排运行器与测试能力检索

参考REQ-KAR-029“预编排运行器与能力检索”。通用库新增PreparedRuntimeRunner，项目适配器实现WaitForNextSampleAsync/Read/Describe/Timeline；有序动作包含条件及领域调用。每次观察读取新样本，仅执行当前动作一次，执行后等新采样才判断结束；固定采样上限及墙上时间安全超时不成为Gameplay权威时钟。外层TestPipelineExecutor继续负责准备、分析、取消和清理。

测试能力保存在项目test-scenarios.json的可选capabilities中：features、adapterPaths、actions、sampleFields、timeDomain。适配器路径必须纳入测试paths以冻结版本；检索同时提供显式能力和图谱源码候选，后者未经运行证明。Agent查询入口project_test_capabilities，制定计划先复用，再登记缺口。

复现参数由项目按显式白名单提供，包含输入、适配器标识、依赖版本、可选种子与时间域，写入同次尝试的封存证据。右侧显示通过/总数和阻塞，断言链接到本次样本并展开数据，日志收起。

机器测试：纯.NET模拟时钟检查动作顺序、一次执行、动作后重新采样、条件不满足、超时、外部取消、时间域错误、字段边界及清理；注册表检查能力字段、版本变化及查询结果。真实Unity先核对工程/Console与场景未dirty，再跑已有Buff和预编排Gameplay精确入口，通过MCP实际回执与封存样本判断；不保存场景、不正式构建、不触碰三狼。背景浏览器检查右侧摘要、样本跳转、复现信息与页面错误，不截图、不抢鼠标。普通任务自动执行的现有回归继续覆盖，默认两轮修复和独立复审不改变。Unity未就绪需记录未联调，不能填通过。

人工验收：执行任务结束后右侧出现测试摘要；点击失败断言查看对应样本和复现参数；打开测试复现可重复已有场景。机器和独立审查通过后仍由用户确认关闭。

## 实施步骤

1. **Karolina 通用诊断库**：新增 `Karolina.Testing` 独立程序集及 UPM 包；目标框架面向 Unity 2022.3 的 .NET Standard 2.1，桌面宿主通过项目引用复用。提供不可变会话/事件模型、可选时间轴坐标、并发安全的有界异步 JSONL 写入器、显式刷新/关闭及接受/写入/丢弃/失败计数。刷新屏障也必须受限，取消的刷新不能在队列里遗留无限控制项。后台 IO 失败可查询，不静默吞掉。增加 netstandard 构建与纯 .NET 回归用例。
2. **验证会话关联**：为现有 `TaskVerification` 的每次执行生成统一会话和事件日志，保留真实机器回执、冻结输入指纹和执行状态。明确区分真实失败、未运行、中断、执行状态不明及诊断证据不完整；只有真实失败消耗修复预算，状态不明或证据不完整时必须重跑后才能继续写入。
3. **修复预算与独立复审**：统一设置默认修复轮数改为 2；每次代码修复后由独立 Codex 子 Agent 审查差异/需求/测试，并保存审查回执。审查失败或不可用时暂停机器验收，不冒充通过。
4. **项目适配合同**：定义项目注册的场景、准备、输入、采样、分析、清理能力。通用核心不引用 Unity；包内独立的可选 Unity 程序集提供真实 `Update` 帧等待和 `UnityFrame` 诊断坐标，取消、禁用和销毁均结束挂起等待。项目仍负责 Unity Test Framework/UnityMCP 场景注册与帧同步 Tick 适配，时间轴无 Tick 时不伪造 Tick。
5. **失败诊断升级**：检测两轮失败和长时间无进展，生成受限的诊断增强配置，保留失败前后采样与原始测试定义；达到修复上限时停止生产修改，等待用户决策。
6. **FrameSyncMoba 垂直验证**：先从现有 Buff/Gameplay 测试选取可隔离的周期治疗 Buff，用测试夹具预置单位与 CombatSystem、通过 `BuffHandler.Apply` 注入、采样四个逻辑 Tick、执行机器断言并封存异步诊断；另用 PlayMode 测试验证通用流水线能等待真实 `Update`、记入 UnityFrame、响应取消/禁用并清理夹具。随后再选一项项目功能 PlayMode 用例验证预编排真实运行态。不操作鼠标、不改场景 YAML、不正式构建，不触碰三狼营地内容。
7. **Karolina 展示与回归**：在已有任务验证入口显示会话阶段、真实断言结果、诊断完整性、审查状态和可打开的本机日志；确认旧记录兼容、关闭程序后记录可恢复。

## 接口边界

- `Karolina.Testing` 是由 Karolina 对项目交付的独立通用程序集/UPM 包；不依赖桌面宿主、Unity API 或特定项目类型。Unity 项目通过 UPM 引用该包，其他 .NET 项目可引用其程序集。
- `Karolina.Core` 负责桌面宿主的任务编排与验证闭环，并通过项目引用使用 `Karolina.Testing`；UnityMCP 与 Unity 生命周期由可替换的项目适配器连接，Core 不引用 Unity 程序集。
- `TestTimelinePosition` 表示 `(domain, value)`，domain 由适配器声明；墙上时间和进程单调耗时始终存在。时间轴为空是合法状态。
- 会话日志为诊断证据，不定义测试是否通过。唯一通过来源是计划冻结的机器断言和测试运行器成功终态。
- FrameSyncMoba 的 Tick、对局与玩家上下文只能由项目适配器填充，不能写入 Core 固定字段。
