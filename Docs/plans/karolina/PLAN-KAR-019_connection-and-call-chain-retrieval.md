## 实施细节与编码顺序

1. Core 增加独立连接计时器，Codex 与 MCP 的校验、启动、握手、工具目录、身份核对分别计时。Desktop 后台连接协调器负责并发隔离、取消、有界重试；手动刷新与自动启动共用服务。账号和模型读取并行，保留模型分页及错误处理。
2. 前端不再等文档等准备完成才启动连接，也不自行重复调度自动重试。状态栏显示当前阶段和就绪状态，原连接入口展开固定阶段耗时，默认无 CLI 或大量日志。
3. 在已经读取的 C# 索引块上建立不可变、有界的方法调用位置索引，清除注释和字符串中的伪调用。按方法名给出调用位置及包含该调用的方法线索；同名、实例类型未解析等情况标明启发式。检索返回调用位置的真实块，并保留指纹、权限和历史过滤。优先分配相关入口、配置和测试，限制总数和上下文预算。
4. 每轮独立记录初始资料、补查与原文读取次数/耗时/字符，以及 Codex 实际 token 回执；累计 token 与缓存分别显示，缺失保持未知。折叠摘要不预测费用、不把字符当 token。

## 机器测试与 Agent 审查设计

连接测试使用可控延迟和失败的 ICodexSession/HTTP 夹具，覆盖握手成功但模型失败、重复并发、退避上限、手动重试和退出取消。真实 Codex 只连接并读取账号/模型，不默认发起模型任务。Unity 未开启时记录不可达，不能称联调通过。

调用检索夹具包含跨文件调用、同名方法、注释/字符串、配置及测试、过期文件、撤销读取权限。新的真实工程问题先冻结预期源码和答案边界，随后分别运行有/无 RAG；记录源码指纹、完整性、耗时和含缓存 token，失败全部保留。不得把已写进本计划的测试答案当成独立发现。高风险完成后独立只读 Agent 审查。

### RAG 与常规搜索对照

两题分别检查弹体结束/实体回收与 AoE 过滤/稳定排序。每组都有原生只读搜索能力，使用当前 Codex 账号的 `gpt-6-luna/low`，DeepSeek 关闭；答案对照冻结源码，并逐条核对引用。不是 Unity 行为验收。三轮均保留全部结果，不用最优一轮代表最终效果。

| 轮次 | 常规平均耗时 | RAG 平均耗时 | 常规未缓存输入 token | RAG 未缓存输入 token |
|---|---:|---:|---:|---:|

最终四次问答都完成。两组覆盖预定 8 个关键事实；此项只是模式覆盖，另以源码人工复核答案边界，不能当成正确率。最终 RAG 9 条结构化引用行范围和原文均吻合，预定源码结构化引用覆盖 5/5；常规 5 条均吻合、结构化覆盖 3/5，原因之一是 AoE 答案把路径写进正文而未填引用数组，不能据此声称它没有找到源码。冻结源码哈希没有变化。

最终 RAG 仍发生两次超 60 行读取请求，宿主拒绝并给出可行分段后模型修正；明确工具说明只能减少误用，不能保证首次请求正确。没有放宽读取边界。调用线索让 AoE 筛选实现进入初始上下文，减少泛用 Clear 方法噪声，但最后一轮没有稳定速度或用量收益。不得把这些小样本换算成费用节约；缓存、重复题、网络及模型随机性影响明显。

本批真实模型调用共 14 次：三轮两题两组共 12 次、两个实际宿主检索联调各 1 次；连接计时和浏览器协议夹具没有模型调用。最终实现之后的结果是最后一轮 4 次问答与最后一次宿主联调，前两轮不是最终程序集证据。
