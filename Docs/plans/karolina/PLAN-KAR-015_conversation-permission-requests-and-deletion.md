## 执行

1. 移除对话页访问权限下拉和权限面板入口；后端忽略旧客户端Access值，按统一设置编译每次操作的有效范围，原生Codex会话仍只读。
2. Core PermissionRequestBroker管理申请与异步完成源，绑定工程、threadId、每轮唯一runId和taskId；独立JSON原子保存申请状态。每轮最多3项，等待最长5分钟。禁止扩权私有状态、原始素材与第三方，允许明确申请其它具体子位置。
3. 会话MCP project_request_permission登记后等待；人工专用API检查原轮次仍运行、未停止且身份匹配才授予。批准后限定工具同轮可使用，拒绝/取消/超时不授予。存储失败回收新授权并向Agent返回失败。
4. GitRollback分离Prepare只读预览与GrantPrepared授予；冻结提交和当前文件哈希。project_rollback只接受当前对话本轮的批准，先占用涉及位置，再消费单次授权并恢复；不改索引和分支，内容变化拒绝并回收。
5. 前端显示原因、范围、期限与批准/拒绝按钮，列表标记待批准。不自动跳页，不占目录等待。授权绑定thread/run，写工具还核对Broker批准状态；本轮停止/结束、任务待审批和规则到期均回收，重启清理孤立授权。
6. 左侧对话列表提供删除按钮和明确确认；运行中拒绝。确认后Codex归档、原子更新本工程列表并释放该空闲子会话。需求/计划/审批/证据保留，退回任务无原会话时新开对话。
