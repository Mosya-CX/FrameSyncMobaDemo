# 任务验证执行与修复追踪

## 目标实现

任务显示独立验证清单、每次执行与失败原因、修复轮数和人工待验收状态；审批可查看同一验证记录。普通模型总结不能将验证项变绿。

## 技术方案

验证定义存当前任务参考计划的verificationChecks元数据，包含稳定ID、中文标题、kind、命令或已注册只读工具、参数、输入文件paths和超时。Core持久化状态机与修复预算，Desktop实现执行器依赖。project_verification_list/run仅在当前任务轮次可调用。命令运行使用原有Codex只读沙箱，退出0只证明该命令检查通过；Unity仅允许tests-run并解析真实计数，不自动正式构建。其它注册工具必须只读、非GUI、非构建；外部工具在同一只读沙箱运行，自标只读不是授权边界。回执仅证明工具执行完成。验证前后核对指定输入文件SHA256；变化使结果过期。失败后首次受控写入开启一轮修复，写入即使已有通过项失效；复测仍失败且到上限时阻止下一轮受控写入。所有失败尝试保留，停止/断线/重启未完成执行标记中断，不伪造终态。

## 边界情况

无定义、无真实测试、Unity离线、无权限、工具变更、超时或输出不完整须明确待处理。外部UnityMCP及拓展工具自主权限管理，不能声称受控写入口的轮数限制能约束外部所有写入。任务启动已登记定义立即冻结（含工具声明指纹），不允许首测前弱化或删除；允许追加检查，追加后同样冻结。定义变化不能复用通过记录；文件变更后重新验证。沙箱初始化故障标记未执行，不冒充工程测试失败、不额外消耗修复轮；未执行回执不能掩盖此前未解决的失败。聊天状态和待处理入口使用单worker合并异步核对，10秒短快照且文件元信息变化立即重查；核对中不显示当前通过，文件变化或无法核对使原通过失效。审批及显式验证完整核对真实内容。人工审批始终独立。

## 验收条件

真实隔离命令失败→受控修复→复测通过，保留前次失败；超限阻止继续受控修复，停止/超时/断线/重启不通过。当前对话及审批显示同一清单，不泄露CLI到日常UI。不运行正式Unity构建，不截图。

## 附录

默认1轮修复，沿用设置0–3；任务记录保存在关联工程.karolina/state。没有验证定义显示未配置而非通过。
