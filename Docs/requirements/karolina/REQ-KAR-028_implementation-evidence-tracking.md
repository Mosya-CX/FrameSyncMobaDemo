# 需求实现证据追踪与过期复核

## 目标实现

用户查看一份标记为“已实现”的需求时，可以看到它关联的已关闭计划、源码文件、测试文件、各自的记录指纹和计划里登记的机器/人工验证结论。界面明确区分“文件当前存在且指纹匹配”与“测试实际运行通过”，不把代码存在或关联资源伪装成验收通过。

Karolina 自动维护实现证据快照。需求正文出现新演进、关联计划不再关闭、计划证据引用发生变化，或源码/测试文件缺失、指纹变化时，系统提示原因并将实现状态恢复为“待实现”。需求生命周期仍为“激活/废弃”，不受实现状态重置影响。

旧版“已实现”记录没有证据快照时，系统先展示已有证据并尝试建立基线；证据不完整或无法访问外部仓库时显示“需要复核”，不得仅因缺少历史快照推断实现已失效，也不得伪造哈希或测试结果。

## 技术方案

- 复用需求元数据 `evidence` 中的源码/测试引用，以及关联计划元数据 `requirements`、`requirementRefs`、`resourceRefs`、`externalRefs` 和计划 `evidence`/`assessment`。不把 `sources` 旧材料当成实现证明。
- 在需求元数据增加单份当前 `implementationEvidenceSnapshot`，记录需求正文 SHA-256、检查时间、已关闭计划编号/正文指纹/关联证据指纹，以及源码与测试的路径、仓库、SHA-256 和证据类型。它是可重建的当前快照，不另建历史日志。
- Core 负责只读收集证据、验证根路径边界、分类和哈希；Desktop 暴露查询与复核接口；前端在需求文档的“实现依据”面板呈现计划、文件、机器/人工验证和失效原因。
- 本工程文件可在目标工程根目录内读取；外部仓库只有当其路径与 Karolina 当前安装/源码仓库根目录完全一致时才允许本机哈希。其它本地目录或 HTTPS 仓库只显示未核验，不跟随任意元数据读取。
- 首次扫描旧“已实现”记录时，仅在至少存在一个已关闭关联计划、至少一个源码引用和一个测试引用且所需哈希都能核对时建立基线；无法核验的旧记录显示复核提示但不批量降级。基线建立后，明确失效会自动重置为“待实现”。
- 标记为“已实现”时要求存在可核对的已关闭计划、源码和测试引用；测试运行状态原样展示计划证据，不由文件哈希推断。重新记录实现后写入新快照并清除过期提示。

## 边界情况

- 历史计划引用的需求正文指纹不同于当前正文时，展示历史引用差异；如果已有当前实现快照没有被破坏，不因迁移前的旧快照自动批量降级。
- 已记录的源码/测试被删除或 SHA-256 变化，属于明确失效；提示具体路径并恢复待实现。计划资源声明为删除的文件以“已不存在”作为有效结果。
- 计划正文、关闭状态或与本需求相关的证据引用在建立基线后变化时，提示复核并恢复待实现；关闭计划本身仍不可重新打开。
- 未登记 SHA-256、路径非法、符号链接、外部仓库不在允许根内或仓库离线时标记“无法核验”，不把未知误判成失效；无法建立新基线时拒绝标记实现并说明缺少项。
- 并发编辑时按需求元数据指纹做乐观并发校验；扫描期间文件再次变化则本次不写回，后续重试。扫描在后台执行，不阻塞打开文档和参考资料列表。
- 多个历史计划引用同一文件时按计划登记的证据分别展示；不把人工导入的模型/动画等非源码资源分类成 Agent 源码或测试。

## 验收条件

1. 已实现需求的详情能查看当前状态、关联已关闭计划、源码/测试路径、证据说明、存储与当前 SHA-256 是否一致，以及计划明确记录的机器/人工验证结果。
2. 列表/启动后台核查已有快照；打开单份需求可即时复核。后台结果不阻塞界面，失效时状态栏/消息提示需求标题、失效原因和已恢复待实现。
3. 修改需求正文的新演进会清除旧快照并保持需求生命周期激活；仅格式修正更新快照正文指纹，不重置实现状态。
4. 跟踪中的源码/测试文件丢失或变更、已关闭计划状态/内容/相关证据变化后，自动把实现状态恢复为待实现；并发改动不会覆盖新元数据。
5. 旧数据证据缺失或外部仓库不可访问时显示“需要复核/无法核验”，不自动猜测已实现，也不把缺失当成内容变化。可核验的旧记录能建立一次性基线。
6. 状态变化会进入现有文档索引/RAG结构化状态，检索不得继续把过期“已实现”作为当前状态。
7. 不访问任意外部路径、不运行 Unity、不改 Unity 代码或资源；机器检查与用户人工验收分开记录。
