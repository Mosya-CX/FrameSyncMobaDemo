# 需求实现状态与参考资料筛选

## 目标实现

展开参考资料后，搜索、需求案/计划案切换、状态与领域筛选、标签浏览和文档列表都在同一个可滚动内容区内；“参考资料”标题保持可见。

需求案的生命周期状态与代码实现进度分别表达。需求案生命周期只使用“激活/废弃”；“已实现”是独立实现标记，不是生命周期状态。部分实现或尚未完整满足的需求仍保持“激活”，只有目标已完整落地时才能标记“已实现”。需求正文发生新的需求演进后，自动恢复为待实现；纯格式修正不重置。

AI 对话的参考资料选择器同时展示需求案和计划案，并提供可组合的多选筛选：文档生命周期状态、需求实现状态、需求现有模块/领域、关联真实资源类型。筛选默认排除废弃需求案和已关闭计划案，用户可以主动勾选重新显示。需求分类直接采用现有模块/领域元数据，不另造“功能/缺陷/优化”分类。计划被选中时，其关联真实文件可逐项勾选，默认全部选中；需求案与计划案的生命周期不互相套用。

## 技术方案

- `status` 保留文档生命周期语义；需求的实现进度放入独立 `implementationStatus` 元数据，旧需求没有该字段时按“待实现”读取。
- 文档详情提供“标记为已实现/恢复待实现”操作。写入前校验元数据哈希，防止并发覆盖。保存带需求演进说明的新正文时，原子更新演进正文和实现状态。
- 参考资料筛选器由标签复选框组合状态、实现状态、模块/领域和资源类型。资源类型依据已登记真实资源的扩展名和路径分类，不按目录猜测资源语义。
- RAG 的索引、证据结构和返回内容同时携带生命周期状态与需求实现状态，并在重新读取证据时核对元数据，避免把“激活”误写成“尚未实现”或把旧状态当作当前状态。

## 边界情况

- 展开面板在小窗口和长列表下限制最大高度；滚轮滚动整个资料内容区，列表本身不再另设纵向滚动条。

- 历史需求没有实现状态字段时使用“待实现”，不得自动猜测为已实现。
- 废弃需求案与关闭计划案默认隐藏，但可通过生命周期筛选恢复显示；筛选器不改变文档状态。
- 需求演进更新后实现标记回到待实现，需求生命周期仍为激活；部分实现仍归为激活，不能因存在部分代码而标记完整实现。
- 没有关联资源的计划可按“无关联资源”筛选；失效或被删除的资源引用不能被伪装成当前资源。
- 元数据哈希过期、目标不是需求案或状态值非法时拒绝写入并提示刷新；不覆盖并发更新。

## 验收条件

1. 用户可在需求文档页独立标记和恢复“已实现”，生命周期始终保持“激活”。
2. 需求正文记录新的演进后实现状态自动恢复为待实现；无演进的格式修正不触发重置。
3. 对话参考资料默认同时展示激活需求与未关闭计划，默认隐藏废弃需求和关闭计划；生命周期状态、实现状态、需求模块/领域、真实资源类型均可多选组合。
4. 勾选计划后显示其已登记真实文件，默认全选并能逐文件取消/恢复。
5. 检索证据明确区分文档生命周期和需求实现状态；旧元数据指纹被拒绝。
6. 机器回归覆盖状态迁移、演进重置、筛选组合、资源分类和真实 WebView2 操作；人工验收仍由用户完成。
7. 参考资料展开后，搜索、类型、筛选、标签与文档列表共用一个有高度上限的滚动区域；外层标题固定，文档列表没有独立纵向滚动。

## 需求演进

### 2026-10-10：新增实现标记与对话参考资料筛选

用户批准为需求案增加“已实现”标记，并要求参考资料支持状态、需求分类和关联资源类型筛选。确认需求分类采用既有模块/领域元数据；部分实现的需求继续处于激活生命周期。实现进度独立于生命周期，需求发生新演进时恢复待实现。

### 2026-10-10：参考资料整个展开区滚动与全量需求状态核查

用户指出只让文档列表滚动不足以浏览筛选区域。参考资料展开后的全部控件改由一个滚动容器承载，列表不再单独滚动；本次同时依据工程源码、需求证据和关联计划盘点全部需求实现状态。需求生命周期保持“激活/废弃”，实现进度独立写入 `implementationStatus`。
