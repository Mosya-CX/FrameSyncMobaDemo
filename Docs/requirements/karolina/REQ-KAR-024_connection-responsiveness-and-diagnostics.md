# 连接响应与耗时诊断

## 目标实现

打开 Karolina 后，Codex 与 Unity 在后台分别尝试连接，不等待外观、文档和工具目录加载。状态栏简洁显示当前阶段；点击查看各阶段耗时、失败阶段和自动重试时间。连接、模型可用、目标工程核对是不同状态，不能伪装成同一种成功。

## 技术方案

连接服务由 Desktop 宿主拥有生命周期；每个提供方同一时刻仅有一次连接尝试。启动、手动操作和自动恢复复用同一入口。重试采用有界退避，手动连接可立即触发；忙碌或 Unity 构建期间遵守既有操作限制。Codex 握手完成后并行获取账号与模型，模型分页仍按游标顺序；模型未准备好时发送不可用。

Core 使用线程安全、有界的连接计时器记录阶段、单调时钟耗时和尝试次数。诊断只记录固定阶段名称及结果，不记录凭据、环境变量或完整请求。运行时完整性校验不因性能优化而取消；Unity 必须核对工程身份，不能仅凭端口可达宣布连接正确。

## 边界情况

- 一个提供方失败不阻塞另一个；失败不能让界面永久停留在连接中。
- 用户退出取消后台操作，重连不得终止其它对话的任务。
- 构建、工具操作或任务占用导致暂缓，应显示暂缓，避免反复报错。
- 分阶段计时区分本机校验、进程启动、协议及远端响应；没有实测不宣称硬件或网络瓶颈。
- 状态自动更新不得切换页面，不恢复上次页面。

## 验收条件

重复冷启动与断线恢复，比较从启动到模型可用、Unity 身份核对完成的耗时。慢账号、失败模型页、错误工程、并发连接、取消和退避都应有明确回执。隔离协议与浏览器检查不能代替真实 Codex 和 Unity 连接计时；Unity 未运行时如实登记限制。

## 需求演进

### 2026-10-08：接受连接优化批次

用户批准“连接体验、调用链检索、连接诊断和检索用量摘要”。由页面串行初始化后发起连接，改为宿主提前后台连接；保留工程身份和权限边界，按实际耗时决定后续优化，不先移除安全检查。
