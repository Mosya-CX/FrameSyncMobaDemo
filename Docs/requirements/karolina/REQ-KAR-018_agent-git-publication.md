# 状态栏 Agent 分批提交与推送

## 目标实现

状态栏增加小型 Agent 推送入口，只面向当前连接的目标工程，额外规则与提交推送常显，运行/失败时显示停止、重试和必要进度，结果详情折叠。没有仓库选择、自身推送、预检查或外部计划批准表单。额外规则可为空，最多 300 字。统一设置独立配置模型，默认 gpt-6-luna，取该模型当前支持的最高挡位；模型不可用就提示，不能暗换高成本模型。

## 技术方案

发布分为准入、只读 Agent 分组、专用 Git 执行三层。模型只接收冻结的差异与计划依据，不持有工程写权限，不接受模型提供的任意命令。禁用此会话的命令、插件、MCP、浏览器等多余能力；原对话和 UnityMCP 不受此发布会话设置影响。执行器只执行检验后的有限 Git 操作。

准入核对人工审批回执和内容指纹。计划自报关闭不能自封批准；人工批准的版本与当前内容不符就排除；涉及未审批计划的共享文件排除。额外规则不能绕开准入。人工已通过的 Unity 任务可提供审批依据；Karolina自身改造由外部Codex负责，不纳入运行时执行与发布；历史自身计划关闭记录不赋予产品自我改造职责。

使用临时索引构建提交树；只更新被批准且未人工暂存的路径，保留其它暂存与工作树内容。引用更新采用预期旧 HEAD 校验。发布开始需本地与远端一致，避免夹带其它未推送提交。重试只能推送该任务产生、已经核对过的提交链。结果持久化到关联工程状态目录。

## 默认推送规则

1. 未审批计划、未批准当前版本、未知来源和夹杂未审批内容的共享文件不推。三狼未完成内容不推。
2. 按功能和职责细分：核心合同与服务、桌面接口、前端交互、测试、需求/规则文档分别成批；强关联改动一起提交，不能拆出无法工作的中间版本。
3. 标题用简体中文“模块：具体动作”，例如“对话：折叠附加参考资料”。正文中文说明变更、原因、真实验证与限制。编号作引用，不代替可读标题；不写泛泛的“更新文件”，不编造测试通过。
4. 不覆盖用户暂存，不 force push，不 pull、stash、clean，不执行整仓库回滚。GitHub 账号沿用用户外部 Git 工具配置的可信凭据管理，不在设置保存密钥。宿主关闭仓库 hooks、fsmonitor 和签名执行；需要外部 filter 的文件拒绝发布或回滚。凭据助手是用户本机 Git 环境，不由模型配置或提供。
5. 额外规则最多 300 字，只能增加约束；任务日志区显示中文进度、批次及失败原因，不显示大量 CLI。

## 边界情况

变更、审批、分支、远端或索引在分析期间变化，停止并重新核对。推送失败保留本地提交，不假装成功，不自动撤销。停止发布保留已完成批次。只支持普通 GitHub HTTPS 仓库；实际 push URL 必须唯一并与核对的 fetch 地址一致；独立 pushurl、多目标或重写到其它地址拒绝。其它协议或共享工作树先用外部 Git 工具。无审批依据的文件排除并解释，不默认 add 全仓库。

## 验收条件

隔离本地裸远端验证中文分批提交、未审批排除、共享文件保护、索引与工作树保留、过期版本拒绝、失败重试范围。验证真实 Luna 调用及最高可用挡位；真实仓库只读核对，不自动执行生产推送。不截图验收。


## 需求演进

### 2026-10-07：收紧到当前工程的小型推送入口

用户明确要求Karolina不能推送自身，只负责当前目标工程，并指出面板冗余。因此删除自身仓库探测、仓库切换、预检查和外部计划批准；回滚仍保留独立能力，不混在推送面板。额外规则最多300字，中文职责拆分、版本准入和索引保护继续生效。历史其它仓库任务不能通过重试绕过当前目标范围。
