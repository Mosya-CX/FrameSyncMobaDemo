# 多对话并行与动态目录修改权

## 目标实现

多个对话可同时讨论、制定计划及执行目标工程任务。共用当前目标工程，不创建仓库副本或独立 worktree。每个对话独立持有 Codex 连接、轮次身份、状态、停止请求和运行记录；切换对话不中断其它对话，停止只影响选中的对话。

修改权按实际操作涉及的子文件夹动态占用，而不是一次任务占住整个工程。Scripts 中不同子系统可以同时修改；父子目录、同一目录及仅大小写不同的目录互斥。

## 技术方案

原生命令沙箱保持只读。绑定会话的 MCP 提供精确文件写入和限定目录的写命令，宿主根据既有内容角色与任务授权验证范围。精确文件写入比较 Agent 提交的预期 SHA256，内容变化时要求重新读取；新增要求目标不存在。写命令使用单次原生 Codex sandbox 权限配置，只允许指定位置写入，其它位置只读，进程及后代由 Windows 作业拥有。

修改权以操作为单位取得和释放；Agent 思考、阅读与规划不持有修改权。冲突时立即返回 busy，明确本次未执行；Agent 应先处理其它不冲突工作，然后重试，不在工具中排长队或立即反复抢锁。

后台定时检查占用记录。默认 120 秒没有文件活动即请求回收；先取消操作、终止自有进程及后代，再释放目录。取消不等于已经结束，回收中的目录仍不可被其它任务取得。单个命令另有最大执行期限。退出、失败和停止都走相同清理流程，部分修改保留并需要核对，不假装全部成功或完全未改。

共享目标工程的任务审批记录相互独立。精确文件操作记录持有修改权后实测的前后版本；跨任务接力修改使旧文件审批版本失效。普通命令和外部 MCP 调用不自动证明逐文件作者，未知来源继续要求确认，人工动画和模型不能因为目录内发生变化就归为 Agent。

## 边界情况

修改权不是用户权限：目录空闲也不能修改 RawAssets、3rd、第三方原目录、Git、私有状态或未授权规则/工具位置。规则授权仍有期限，任务进入待审批回收。

目录协调强制覆盖 Karolina 提供的文件与命令写入口。外部 UnityMCP、拓展工具及人工编辑继续自行管理权限与操作，不因这些调用成功就宣称它们遵守本修改权协议。无法取得逐文件写入证据的内容保持未知；所有审批与发布仍核对当前版本指纹。精确文本替换在临时文件准备完成后再次核对目标指纹，新增不能覆盖已有文件；但无法与不使用本协议的外部编辑器实现完全原子的跨进程比较交换，人工或UnityMCP应避免同时写同一文件。多个文本写入不构成整批事务，失败时明确保留并核对已发生的部分结果。

Karolina 运行时不负责自身改造，不执行 Karolina 自身计划，不推送自身源码；这些由外部 Codex 维护。自身文档可作为历史参考，运行时不拥有其修改权限。

## 对话表现

空对话没有右侧 Agent 状态占位；发送后出现，打开有内容的历史对话显示最近一轮。状态、摘要与消息分开。已知活动标题用确定的中文译名；未知外文摘要直接用弱化、斜体样式展示，不添加重复的“公开摘要（模型返回外文标题）”或逐项“查看模型原文”。列表标识执行中的对话，草稿切换保留。

## 删除对话

列表提供删除入口，每次需要明确确认。运行中先停止并等终态，不由删除操作强杀。人工确认后归档底层Codex会话并从当前工程列表持久移除；不删除需求案、计划案、任务审批、取证或文件，不宣称物理抹除Codex历史。原对话删除后的待再执行任务通过新对话承接，原任务编号、开始基线及退回意见保留。外工程对话与未确认请求拒绝。

## 验收条件

验证两个真实对话同时执行、分别停止和恢复历史；不同子文件夹可同时占用，父子/大小写冲突立即返回 busy；空闲到期取消后仍持有修改权，进程确实结束后才能重试。实际单次沙箱验证目标子目录允许写、旁路子目录拒绝写，规则/私有状态不扩权。验证空状态隐藏、精简摘要、当前工程唯一发布入口。测试使用临时工程，不修改三狼，不截图验收。

## 附录

本轮用户明确选择共用工程目录、动态占用子文件夹；占用失败的 Agent 先做其它工作再重试，并要求自动检测和回收长时间无操作的占用。

## 需求演进

### 2026-10-07：删除确认

用户要求支持删除某次对话且需要确认。采用列表删除和确认对话框；运行中拒绝，底层归档而非物理清除。关联任务和证据继续独立保存，避免删除聊天破坏审批追溯。
