# 工程知识检索与关联取证

## 目标实现

用户不预先勾选资料也能以自然语言找到具体文档章节、源码实现及其明确关联。自动资料默认收起，可打开来源、行范围、命中片段与索引时间。手动资料搜索与 Agent 使用同一检索服务，保留需求/计划筛选和默认排除废弃/关闭资料。

## 技术方案

Core 拥有工程独立的分块索引、检索与可替换的查询改写接口；Desktop 负责凭据、权限、工具及 UI 组合。Markdown 按标题层级和有界窗口分块，脚本按声明及连续行窗口分块；符号识别是静态启发式，不冒充编译器调用图。块保存文档身份、章节、行号、标签、SHA256、索引时间。索引保存在目标工程 `.karolina/state`，源码仓库不保存产品文档。

默认复用当前 Codex 对话中的 GPT 进行语义理解，沿用对话所选模型、挡位和已登录账号。宿主先以 BM25 召回初选资料；GPT 结合对话上下文判断证据是否充分，把自然语言转为中文近义词、英文术语或实际符号，通过 project_search 按需补查并核对返回证据，不另起隐蔽的辅助对话。远程模型推理依赖 Codex 的连接、账号额度和可用模型；本地只是索引与取证，不部署本地模型，也不要求另配 OpenAI API 密钥。手动资料搜索默认是本地词项搜索，不冒充 GPT 已理解。

关键词检索使用 BM25，兼顾中文二元词项、英文部分词、编号、路径和符号。用户允许额外模型 API 时仅可接 DeepSeek，作为可选的前置查询改写；默认关闭，不是上述流程的前提。DeepSeek Chat Completions 只改写检索问题、补充中文近义词和英文代码术语；最多4条查询，每次最多320输出token，8秒超时，15分钟有界内存缓存。原查询始终保留，多个查询的本地 BM25 排名用 RRF 融合；没有向量/嵌入服务，不用模型猜测代替检索证据。凭据缺失、认证/连接失败、超时、无效回执均降级本地检索并提示。

先检索证据块，再按需求/计划明确引用、实际资源关联和静态图谱邻接边有界补充。注明文档目标、源码事实、资源关联与验证记录的不同证据身份。关联不代表实现通过；外部仓库资源只显示关联声明，不自动索引或读取。Unity 二进制和 YAML 不作为长正文灌入上下文，只展示可信文件属性、已知引用和已登记说明；不臆测内部语义。

索引维护采用后台单工作者、变动合并、失败退避和定期核对；按文件指纹复用未变块，删除/改名清理旧块。发布完整快照，搜索不等待重复全工程扫描；初次建立由异步请求等待。检索前和打开来源时均验证工程边界、链接、读取策略和文件指纹；过期块不得当作当前证据。持久化块在启动后须从真实原文重新生成才能返回，不信任可编辑缓存中的正文。

DeepSeek 固定官方 HTTPS 地址且禁止自动重定向；只发送检索问题，不自动附加工程文件。自动检索使用本轮用户输入，手动理解搜索使用搜索框文字，Agent 也可通过 project_search 主动提交查询。查询中粘贴的代码、文档和日志也属于发送内容，界面明确说明；工具说明要求 Agent 不把工程正文用作查询。密钥仅保存 Windows 凭据管理器，不进入工程设置、日志或正文；读取接口不返回密钥。默认关闭，用户填密钥并启用后才调用，API 有正常用量费用。

### 结构化取证与有界补查

来源独立保存文档状态、版本、元数据路径及字节指纹、正文指纹、采用编码和当前/历史身份。人工登记与机器验证分别显示；文档登记不是宿主已独立核验的人工审批，缺少登记不推断通过。project_search 每轮支持1–3个简短查询，同一对话轮次最多2轮，按查询及文档/代码轮转分配最多24个来源，直接命中优先于关联。额度、凭据及已提供来源由各轮次独立拥有，旧请求不能影响新轮次。

Agent 用 project_read_evidence 提交本轮已提供的来源ID（也接受已提供文件相对路径或文档编号）和行范围。宿主使用本轮登记的正文及元数据指纹重新读取真实文件；显式提交指纹时也必须匹配。每次最多60行、6000字，源码可在同一已提供文件内明确指定行范围，文档仅限已提供切片，避免历史混入。拒绝未知来源、跨文件猜测、多个不同指纹的别名、越界及过期指纹。引用卡片保存该次核对的准确原文，点击时再次核对；模型概括或自由撰写的引文不会自动成为已核对卡片，历史卡片也不保证文件此后一直未变化。

自动上下文初始预算10000字符，代码与文档交错，验证记录优先，关联和历史随后；单条预览最多1100字符，过长条目跳过后继续处理，包含关系重复片段不重复供给。界面区分候选、实际提供的预览与原文已核对来源，未提供不表示Agent读过。资料情况只表示匹配情况，不是答案正确率。

关闭/废弃过滤覆盖已登记文档的正文与元数据身份；共享代码不随旧计划隐藏。活跃需求的“需求演进”章节默认作为历史排除，需要时显式含历史。不对尚无所有权登记的任意附件猜测专属归属。

设置页显示实际覆盖与遗漏，提供最多200项相对文件路径的明确编码覆盖。BOM优先识别，未指定且无BOM严格读UTF-8；覆盖支持UTF-8、UTF-16、UTF-16BE、GB18030、Windows-1252、Big5。不猜编码、不转写原文件；修改覆盖后异步重建，旧编码证据失效。语义仍由当前对话模型负责，不增加本地模型、额外线程或必需API。

### 可见配置与取证效率

统一设置增加直接可见的“检索与API”分类，DeepSeek API配置不藏在图谱折叠项。提供密码输入、保存/删除密钥、检查连接并获取模型、按工程启用与保存；明确填写顺序、发送范围与费用。空密钥不发保存请求，保存成功清空输入，失败留在页面可见。连接检查只证明认证与模型列表可用，不等于查询改写已实测。官方接口参考：[DeepSeek API](https://api-docs.deepseek.com/zh-cn/)。

模型工具的JSON采用紧凑且中文可读的形式，保持原字段、空值、证据、警告和截断信息；不改变持久化格式和全量图谱UI。一次词项查询内同一块及文件边界只检查一次，跨查询重新检查；返回和打开来源继续核对当前指纹与权限。精确文件关联及节点详情复用同快照的节点/邻接字典。

代码证据按文件附带一次最多24项声明导航，相关声明优先并带原始行号；初始上下文导航最多约650字符。导航由静态声明文本生成，仅用于定位入口，不是编译器调用图、其他正文已读证明或行为验收。复杂语法可能遗漏，截断明确提示；精确方法声明提高排名权重；可先补查方法再读原文，或按导航行号在已提供源码文件中有界读取完整函数。文件路径别名不要求模型猜造#L切片ID，仍只解析本轮登记的文件；文档其它章节和历史仍须先检索。

### 调用线索与用量摘要

对 C# 源码建立有界的调用位置索引：按真实方法声明查询调用位置，同时提供所在方法及其相邻源码块，方便核对调用前准备和后续处理。索引来自已经读取的代码，不额外外发正文；排除注释与字符串中的伪调用。同名方法、实例接收者和动态调用无法静态确定时明确为启发式，不当作编译器调用图。给 Agent 提供的调用位置必须仍通过当前权限、文件指纹、行号和预算检查；源码关系、相关配置和测试分别说明，不把存在测试当成测试通过。

跨模块问题的上下文优先保留实现和调用位置，再补明确配置/测试线索，避免大量同文件相似片段挤占预算。总资料和字符预算保持有界；普通闲聊不强制扩展。沿用当前模型，不新增隐藏对话或必需 API。

每轮对话提供默认折叠的检索用量摘要：初始资料数量、补查次数、原文读取次数、各自耗时及返回字符数；Codex 提供 token 回执时显示本轮实际累计值和缓存部分，缺少回执显示未知。字符、token、费用和答案正确性不互换；不同对话或轮次不得混入计数。

## 边界情况

- 排除私有助手状态、Git、缓存、构建产物、密钥和链接；检索材料不构成指令或权限。
- 读取权默认覆盖工程维护文件；接入方收紧读取策略后，缓存也不得继续返回受限内容。
- 文档历史默认不参与，包括从关联边绕回的历史文档；明确选择含历史时方可检索。
- 无匹配、未启用查询理解、截断、读取失败、索引错误及图谱过期分别提示；不会用低相关片段凑答案。
- 大文件、单文件块数及总块数有上限，超限显示覆盖不足。文件消失不保留当前引用，失败不覆盖最后成功索引。
- 不改变当前任务验证、人工审批或文档自主维护职责；不改变 Unity 工程实现。

## 验收条件

以真实工程问题和隔离夹具对照：章节命中、自然语言近义检索、符号与标签/部分词、相关源码片段、明确关系展开、历史过滤、无答案、改删/改名、权限收紧、工程隔离、索引持久恢复及失败降级。来源可打开并准确定位。测量真实工程索引与查询耗时，机器结果与人工验收分开记录。
