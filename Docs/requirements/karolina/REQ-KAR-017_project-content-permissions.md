# 工程内容权限与任务临时授权

## 目标实现

权限按工程内容角色呈现：C# 脚本、Lua 脚本、游戏资源与配置；在统一设置维护实际位置。指定 Assets 位置可新增、修改、删除。原始素材 RawAssets、3rd、第三方插件原目录只读，可复制到可编辑位置。Assets 外普通文档和日志可编辑，其它工具、构建、配置默认可读和调用，修改需先申请任务授权。规则与模板同样先申请且写明使用期限。

## 技术方案

使用 Codex 命名权限配置的 filesystem read/write/deny 及 network；原生会话保持只读，需要写入时由绑定轮次的 project_write_files/project_run 验证工程内容角色与临时授权，只给本次操作涉及的位置写权限，结束即释放。具体并行协议见 REQ-KAR-019。不用完整访问和“整工程可写”充当内容权限。网络开放。UnityMCP 与拓展工具管理各自调用权限，Karolina 不另建工具限制系统。当前调用权限和能力错误要显式报告，不能回退到无沙箱。

授权记录独立保存到关联工程 .karolina/state，包含任务、位置、截止时间、目的、回收原因。任务进入待审批立即回收；退回执行重新申请，任务不等于一轮对话或整个计划。使用期限到达时结束持有旧策略的工作台自有 Codex 进程树，再重连；不能将 interrupt 请求受理当成权限已回收，再发送时重新编译权限。命名配置以有效路径映射的 SHA256 派生名称；恢复已加载对话前退订再载入，使策略变更实际生效，轮次继承线程策略。普通文档与规则文档采用分离的写根，避免 Windows 父目录 deny ACL 阻止临时重新授权。文档根目录既有文件可直接写，原生单文件权限不保证创建同目录的新临时文件；工作台文档接口由宿主负责原子保存，新文档放在已有需求/计划板块。

默认权限一律取统一设置；AI对话页不再提供访问档位和独立权限入口。Agent需要额外权限时调用project_request_permission；这包括工具/构建临时写权限、规则文档限时权限和一次性Git回滚。人工在当前对话看到原因、具体位置、有效期及回滚来源，明确批准或拒绝。等待期间不持有目录修改权，不能提前操作。批准后只给同轮的限定写工具使用，原生会话仍然只读，无须停止重发。

申请绑定工程、对话、本轮唯一runId及任务。批准API使用人工令牌，Agent的MCP令牌无权批准。每轮最多3个待批准申请，等待最多5分钟；拒绝、停止、断开请求、超时及重启均不授权，旧轮次和重复批准拒绝。批准持久化失败回收新授权。授权记录包含ThreadId/RunId，写工具同时核对申请已批准、任务、对话和当前轮次；普通讨论和任务轮次停止/结束即回收，正式任务进入待审批及期限到达亦回收，后续轮次重新申请。重启收回旧执行环境全部授权，包括崩溃窗口留下的孤立授权；批准记录或回收写盘失败也不允许工具采用该授权。

Git 默认只读。回滚先核对指定文件、固定来源提交和当前内容版本，借用一次性能力。领取后只能执行一次；完成、失败、内容变化都失效。不授权 reset --hard、clean 或修改其它文件，不改变分支与暂存区。

## 边界情况

更具体的第三方只读条目覆盖角色的可写位置，临时授权不能绕开原始素材、第三方、Git 或 Karolina 私有状态。链接和越界路径拒绝。过期记录不因退回而恢复。MCP 和外部工具可能具有独立文件写能力，由各工具管理，这部分不能被声称已受命令沙箱控制。

## 验收条件

验证普通脚本允许写，规则与 Git 拒绝直接写；临时授予规则后可写，待审批后不能再次使用；实际回滚仅恢复指定文件、保留索引并拒绝复用；网络不由 Karolina 限制。不用截图。Windows 不支持的权限规则可见失败。当前原生 elevated Windows 沙箱要求 :root 可读，因此本机读取范围广于关联工程；常见 SSH、云凭据及 Codex auth.json 明确 deny，写入仍仅限工程角色位置。统一设置如实说明此范围。

人工界面与 Agent 图谱 MCP 使用不同令牌；图谱令牌不能调用审批、扩权或发布 API。原生窗口用精确同源根页面请求头传递启动密钥，浏览器地址不含密钥；页面响应 no-store 与 no-referrer，未授权页面和 CSP 头不泄露人工令牌。Codex 文件沙箱显式禁止读取整个 %LOCALAPPDATA%/Karolina 私有数据目录，覆盖 WebView2 数据、用户设置及工作台日志；不能只保护工程内 .karolina 而遗漏浏览器数据。开发用 --serve 入口只用于本机诊断，其启动链接同样属于凭据，不能发给 Agent。

## 附录

本轮用户确认“进入待审批即回收”，并明确 Git 回滚是一次性借用。Codex 0.159.2 当前 schema 的 thread/start 与 turn/start 使用 permissions，不能同时发送旧 sandbox/sandboxPolicy。

## 需求演进

### 2026-10-07：并行操作与产品自身边界

用户明确多 Agent 共用目标工程、动态占用子文件夹，故不再向原生整轮命令开放内容角色的全部写根；改为受会话和本轮令牌保护的单次写操作。Assets/ClientContent、Config、Resources、Shader 作为配置资源默认可编辑。保留第三方源、规则授权期限、待审批回收、Git 专用能力等边界。Karolina 自身需求和计划只读，其改造由外部 Codex 维护。

### 2026-10-07：统一设置与对话内申请

用户删除对话页访问权限与独立权限入口，要求全部额外权限和原有临时权限都由Agent主动申请并等待人工批准。将此前下一轮生效改为同轮限定工具可使用；申请不是自由文本承诺，也不自动扩大原生命令权限。拒绝、停止和程序重启都不能视为批准。
