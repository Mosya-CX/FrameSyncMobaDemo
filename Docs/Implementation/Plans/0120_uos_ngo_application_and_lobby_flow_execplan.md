# ExecPlan 0120: UOS/NGO application and lobby flow

> Status: Completed.
> Parent: `0109_design_conformance_remediation_program_execplan.md`, Gate 10B.

## Purpose

Implement the application-owned client/server flow around the completed
transport-independent FrameSync core: test-account bootstrap, UOS matchmaking
and allocation adapters, NGO connection ownership, deterministic lobby slot and
ready barriers, frozen start payload/version validation, and result delivery.

## Progress

- [x] Inspect installed UOS 1.4.0/1.1.3/2.1.0 and NGO 1.12.2 APIs locally.
- [x] Add formal start/result contracts and version validation.
- [x] Add client/server application states, lobby barrier and installed-SDK
  adapters in Bootstrap only.
- [x] Add focused pure/EditMode tests and Unity MCP compilation validation.

## Discoveries and decisions

- No application-flow implementation currently exists; `GameBootstrap` directly
  advances a local runtime in both build roles.
- UOS SDKs are installed and expose async client ticket, server match-info and
  Multiverse ready/shutdown APIs. Adapters may reference them only from
  `FrameSyncMoba.Bootstrap`.
- NGO owns connection lifecycle; it does not define Gameplay Command or
  AuthorityFrame semantics.

## Context and design

- `Docs/Design/FrameSync_Flow_Integrated_System_Design_v10_2.md`, sections 2-4,
  7-8, 12, 14 and 17.
- Production assemblies: `FrameSyncMoba.FrameSync`,
  `FrameSyncMoba.Bootstrap`; installed `Unity.Netcode.Runtime` and UOS runtime
  assemblies.

## Scope

In scope: `PlayerSlotConfig`, `GameStartConfig`, `GameBootstrapPayload`,
`MatchResultState`, version handshake, application state machines,
`LobbySessionFlowNetwork`, account persistence, UOS and NGO adapters.

Out of scope: changing Packages, provider dashboard configuration, production
heroes/content, network message serialization generated by a specific backend,
or moving transport types into Gameplay.

## Implementation and ownership

1. Put transport-neutral frozen match/start/result contracts in FrameSync.
2. Put test-account, lobby and client/server flow ownership in Bootstrap.
3. Add UOS/NGO adapters only to Bootstrap asmdef.
4. Verify pure state transitions, full ready barrier, version mismatch rejection
   and role separation.

Stable ordering is ascending `PlayerSlot`; player count, slot count and all
critical versions must agree before start. These application states and network
buffers never enter `GameplaySnapshot` or checksum.

## Validation

Unity MCP compile/Console; focused Bootstrap EditMode tests. No live UOS call,
scene mutation or PlayMode test is required for the pure state/adapter contract
slice.

## Failure and recovery

Do not add Packages. If installed API compilation differs, correct only the
Bootstrap adapter; do not weaken the transport-neutral contracts.
